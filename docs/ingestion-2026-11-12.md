# 적재 개선 구현 범위

사용자가 11/12에 승인한 순서: 기존 관측 원천/시각 → 수집 실행 이력 → DART 공시 이력 최소 수집기.

기준 소스: GitHub main 5be1f359caff03e50dcc8c006c8b14dc5dbc4a62. 이전 PC 작업 폴더와 인증은 현재 Linux 환경에서 접근할 수 없으므로 복원한 저장소를 별도 브랜치로 구현한다. 실제 배포본과 저장소 main의 차이가 있어 이 저장소를 통째로 운영에 배포해서는 안 된다. 기존 운영 작업 폴더에 변경을 합친 뒤 배포해야 한다.

1. 기존 premium_snapshots는 열을 바꾸지 않고 보존. 원천 메타데이터는 additive sidecar premium_snapshot_sources에 기록. 과거 원천은 추정하지 않음.
2. collector_runs에 실행 시작·끝·스케줄·요청/관측 심볼·성공/부분성공/실패·실제 신규 행 수를 기록. 수집기가 실행되지 않은 구간은 별도 스케줄 대조 대상이며 실패 행으로 꾸미지 않음.
3. 가격과 sidecar는 D1 batch 트랜잭션으로 함께 삽입. 이미 있는 키는 덮어쓰거나 새 출처로 소급 장식하지 않음. 실행 실패 시 오류 코드만 기록.
4. 글로벌 가격은 공급자·실제 fetch 완료 시각·제공되는 마지막 체결 시각 보존. Kraken의 불명확한 체결 시각은 null. FX 기준일은 원천 표기를 그대로 두고 정밀 시각으로 꾸미지 않음.
5. DART는 feature flag 기본 off. API 키와 명시적 최대 10개 corp_code를 요구. 인증키나 요청 URL을 오류/로그/DB에 남기지 않음. last_reprt_at=N, 날짜는 KST, 제한된 페이지를 끝까지 확인해야 성공. 제한 초과는 partial/truncated. 정정 링크는 추측하지 않음.
6. DART 목록은 공시 사실/메타데이터만 저장. 정정 접수번호마다 별도 사건이며 같은 번호의 A→B→A 변경도 별도 버전. 회사별 완전 조회 워터마크를 하루 겹쳐 조회하고, 장기 중단은 7일 창으로 따라잡는다. first_observed_at과 공시 접수일을 분리. 실제 원문 전문/제출인 개인정보를 저장하지 않음. 신규 유료 API·공개 노출 없음.

검증: 메모리 SQLite로 기존 행 보존·재실행·배치 rollback·부분 관측·원천 시각·fallback·DART 페이지네이션/오류/키 비노출/변경 버전을 확인. 타입 검사와 기존 preview 테스트도 실행한다.

운영 적용 전: 실제 배포 작업 폴더와 병합, Cloudflare 배포 권한 재연결, DART 권한/키·관심 기업·공식 사용 범위 확인. 준비 작업과 운영 적용을 구분한다.
